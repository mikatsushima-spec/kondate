# 実装要件

対象：保護者1名のスマートフォンと、小学校1年生の子ども。日本時間。

## 給食

今日の献立を料理イラストと読みがなで表示。カレンダー・前日・翌日・今日に戻る。未登録と給食なしを区別。端末復帰時は今日、表示中の午前0時は今日モードだけ日付を進める。

PDFをアプリ画面で直接選択 → 対象年月を確認 → 日付・料理・牛乳・休み・行事を解析 → 原本プレビューと編集 → 確認済みの内容を一括保存。同月更新は前回分を1世代保持。他の月は保持。キャンセルや失敗で既存データを変更しない。

解析対象は提供資料と同形式の文字PDF。違う形式と画像PDFは手入力。原本にない料理・日付・牛乳は推測しない。料理名が一致するイラストを採用し、一致しない場合は中立な皿から親が選択する。

## 夕食

別タブで1日1候補を提案。「別のメニュー」で主菜を変え、「前のメニュー」で戻る。同日の候補は保存。確定したメニューだけを夕食の履歴に残す。候補を一巡したら明示して再表示する。

主菜の方向性7種を8献立で実装。副菜は生・切るだけ・酢漬け・レンジ。毎日野菜を別添え。4人分。調理時間は10〜20分を目安とし、炊いたごはんを使用。肉じゃが・カレー・シチューは小さく切り、レンジと鍋を並行する。時間を保証せず火通り確認を優先。

カレーとシチューを合計して週1回以内（月〜日）。確定履歴で判定し、当日分の置き換えは当日を除いて判定。提案の表示、給食のカレーは回数に含めない。履歴は親が補正できる。

出力①献立（主菜・副菜・調理時間）②A4縦雑誌風レシピ画像の生成プロンプト（①②③の図解）③野菜・肉・その他に分けた4人分買い物リスト。写真・手順・材料・プロンプトを同じ献立データから表示する。

## 端末保存・操作

PWA、IndexedDB、バックアップ/復元、オフライン用キャッシュ。コードはGitHub `kondate`。個人のPDFや入力データはリポジトリに含めない。親の入り口は3秒長押し。これは誤操作防止で、アクセス認証ではない。

ホットクックは機種未指定につき未使用。機種別の公式操作番号を検証できた場合だけ今後追加する。写真OCR、外部AIによるリアルタイム提案、複数端末の同期は初版の対象外。
